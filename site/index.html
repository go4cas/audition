How it works

Four steps from
"which one?" to "this one."

You set the stage once. After that, every run makes the answer clearer.

  1. 1

    Cast your roles

    Make a workspace for a workflow, like a software team or a marketing pipeline. Add its roles, in groups if that helps (Visa and Weather in a trip planner, in no set order), a few real tasks for each, and what "good" means as a short star rubric.

    WorkspacesRubrics
  2. 2

    Run the audition

    Pick the contenders and press Start. API contenders answer on their own. For an agent or an app, Audition hands you the prompt to paste in, and you paste the reply back.

    Live progressCopy and paste
  3. 3

    Judge blind

    Names are hidden and the order is shuffled, so you judge the work, not the brand. Rate each line of the rubric with stars, or compare two outputs at a time and pick the better one. Do it yourself, or let an AI judge do it and change anything you disagree with.

    BlindAI judge
  4. 4

    Crown a champion

    The leaderboard weighs stars against tokens, time and cost. When a contender has earned it, make it the champion, and everyone knows which one to use for that role. A new champion starts on trial: if it falls short in real work, restore the old one in one click.

    LeaderboardChampion

What you get

Fair tests, plain words,
no spreadsheets.

Audition is made for the people who actually use the tools, not only the people who build them.

Blind judging, two ways

Each role has its own rubric with weights, like "Practical and realistic, 35%". Outputs show as A, B, C in a shuffled order, so the verdict reflects the work alone. Give stars, or choose Compare and simply pick the better of two: "A is better", "About the same" or "B is better". Want more opinions? Share a guest link: anyone can vote blind, no account needed, and you decide whether their votes count.

Always knows what's next

"Waiting for you" lists everything that needs you: a reply to paste, a run to judge, an outcome to check. It works on your phone too.

An AI judge you can overrule

Let an AI score each output against the rubric, or pick between two, images included. You always have the final say.

A Composer can sharpen each task into a better prompt first. You read and edit it, and every contender gets the same text.

Works with any tool

No API? Copy the prompt into any agent or app and paste the reply back, with files.

Image models like gpt-image can be called directly too. Every picture they make lands in the judge grid.

Built on Vaultbase

One binary.
No other backend.

Audition runs entirely on Vaultbase, a self-hosted backend in a single file. It's also a working tour of what Vaultbase can do: almost every feature in Audition is a Vaultbase feature, used the way it was meant to be used.

Meet Vaultbase
  • Records APIEvery write goes through it, so rules, hooks and history always apply.
  • Record historyRuns, verdicts and champions keep who changed what, and when. Restore an earlier champion straight from its history.
  • RealtimeThe run page updates live as outputs arrive.
  • Encrypted fieldsProvider API keys are write-only. No screen or response ever shows them.
  • Hooks and queuesStarting a run fans out into one job per task and contender.
  • Files and thumbnailsUploads are checked by type and size; the judge grid loads thumbnails.
  • CronScheduled repeats, outcome checks and the stuck-output sweep.
  • Email and pushAlerts when a run finishes, a champion changes, a new champion's trial is over or a check is due.
  • View collectionsThe leaderboard is a view with aggregations, not hand-written SQL.
  • Auth, MFA and audit logSign-in with MFA and rate limits; file downloads land in the audit log.

Install

On stage in
a few minutes.

Try it on your own computer first, with four example workspaces ready to run. When you like it, put it on a small server with one command.

  • Linux or macOS. On a computer you need Bun 1.4 or later.
  • The server installer sets up Caddy, nginx or a Cloudflare Tunnel, plus nightly backups, with an optional copy off the server in Cloudflare R2.
  • Your API keys stay on your server, encrypted.
Terminal
$ git clone https://github.com/go4cas/audition.git
$ cd audition
$ bun install
$ bun run dev
# Open the address it prints, and sign in.
your-server
$ curl -fsSLO https://github.com/go4cas/audition/releases/latest/download/install.sh
$ sudo bash install.sh
# It asks for your domain, email and password.
# Later: install.sh upgrade, status or rollback.
